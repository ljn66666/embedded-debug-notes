# 嵌入式调试笔记

单片机跑不通时，按这个顺序查，比随机换器件快得多。

这些内容来自实际调板子的过程：STM32 / ESP32 / 51 / Proteus。
不写"某某很强大"这种话，只写现象 → 原因 → 怎么验证。

## 排查顺序（我固定按这个来）

1. **先分硬件还是软件**
   单独给单片机供电，烧一个最简单的点灯程序。
   灯不亮 = 硬件或烧录链路；灯亮 = 业务代码。
   这一步能砍掉一半排查方向。

2. **看供电，不是看标称**
   万用表量板子上的实际电压。「随机死机」「串口乱码」很多是电压在抖。

3. **看通信**
   串口能不能认到、波特率对不对、TX/RX 有没有接反、共地了没有。
   这几项看着蠢，但每年都有人栽在上面。

4. **才是看代码，且先看最近改了什么**
   刚改的那几行嫌疑最大。

5. **还不通就缩小到最小可复现工程**
   删掉所有无关的东西，只留能复现故障的最少代码。
   很多时候在删的过程中问题就暴露了。

顺序的意义：每一步都能排除一大片可能，而不是随机替换变量。

## 12 条常见现象速查

| 现象 | 先查什么 |
|---|---|
| 编译报 `No such file` | 缺 `.h`；检查 include 路径和文件是否真在目录里 |
| 烧录失败 | BOOT0 是否接地、SWD 四根线是否接反、目标板是否单独供电 |
| 程序下进去不跑 | 复位脚是否被拉低、晶振有没有起振 |
| 串口全是乱码 | 波特率与晶振不匹配；8MHz 晶振别直接跑 115200 |
| 串口收不到 | TX/RX 接反、没共地、驱动没装 |
| 卡在 `while` 等标志位 | 外设时钟没使能（RCC 忘了开） |
| ADC 一直是 0 或满量程 | 通道与引脚对不上、参考电压没接 |
| 定时器时间不对 | 分频与重装值算错；注意是向上计数 |
| 中断进不去 | NVIC 没使能，或优先级分组配错 |
| 一开外设就死机 | 电源带不动，量板子实际电压 |
| 显示屏花屏/不亮 | 初始化时序、供电、背光；SPI 模式选错 |
| 换台电脑就打不开工程 | Keil 版本与器件包（DFP）没装 |
